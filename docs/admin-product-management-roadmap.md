# Admin product management roadmap

This note records planned admin architecture extensions without adding fake UI fields before the database supports them.

## SEO override fields

Current product SEO is generated by the public product view layer. If manual overrides are needed later, add explicit nullable fields instead of overloading the internal product name:

- `seo_title_override`
- `seo_description_override`
- `h1_override`
- `canonical_override`
- `og_image_media_id`

Migration impact:

- Add nullable columns to `products`.
- Extend the Drizzle schema and product services.
- Update `buildPublicProductView()` to use overrides only when non-empty.
- Show override fields in admin with generated fallback preview.
- Revalidate catalog, SEO route, sitemap, and search after saving.

## Bulk operations groundwork

Useful bulk operations for the next milestone:

- publish / unpublish selected products
- move selected products to category or subcategory
- regenerate SEO preview after taxonomy or naming rule changes
- sync image fallback for products without primary image

Implementation shape:

- Keep bulk use-cases in `lib/services/products.ts` or a dedicated `lib/services/product-bulk.ts`.
- Validate selected IDs server-side.
- Use transactions for multi-row edits.
- Revalidate affected public catalog paths after the transaction succeeds.
- Keep the first UI small: checkbox selection, action menu, confirmation dialog.

## Admin diagnostics

Useful low-cost diagnostics:

- current `PUBLIC_CATALOG_SOURCE`
- whether a product is active and visible in DB mode
- public display name and canonical path from `buildPublicProductView()`
- product image count and selected primary image
- missing DN/PN/material/connection warnings
