# Admin Workflow Stress-Test (контент-менеджер)

Документ фиксирует UX-трения, bottlenecks и риски при **реальной** работе в админке (серии действий: товары, импорт, категории, медиа, контент, навигация).  
**Не цель:** большой redesign или новые крупные фичи.

Оценка сложности: **S** — до ~1 ч, **M** — 0.5–1 дня, **L** — несколько дней / затрагивает несколько модулей.

---

## Исправлено в этом спринте (код)

| ID | Что сделано |
|----|-------------|
| **QW-IMPORT-01** | Импорт: две отдельные `<form>` давали разный контекст `useFormStatus` — во время Apply кнопка превью оставалась активной (риск гонки / double-submit). Объединено в **одну форму**: default `action={preview}`, Apply через `formAction={apply}` + `formNoValidate`, обе кнопки блокируются на время любой отправки. |

| **QW-NAV-02** | Подсветка активного пункта: на `/admin/products/import` больше не подсвечиваются одновременно «Товары» и «Импорт» — исключение для префикса import. |

## Quick Wins (минимальные правки, высокий эффект)

### QW-PROD-01 — Длинная форма товара: «где я» и save

| Поле | Значение |
|------|----------|
| **Severity** | Medium |
| **Workflow** | Создание/редактирование товара (много секций, specs, блоки) |
| **Reproduction** | Открыть `/admin/products/new` или `[id]`, заполнять нижние секции, сохранять редко. |
| **Почему больно** | Менеджер теряет контекст длины формы; без привычки к sticky/footer легко забыть сохранить до смены вкладки. |
| **Минимальный фикс** | Убедиться, что `AdminStickyActions` / футер всегда в зоне видимости на типичном viewport; при необходимости — короткая подсказка «изменения не сохранены» рядом с primary (уже есть guard — проверить сценарии только client state). |
| **Сложность** | S |

### QW-CAT-01 — Reorder категорий: много мелких submit

| Поле | Значение |
|------|----------|
| **Severity** | Low–Medium |
| **Workflow** | Массовая перестановка порядка на `/admin/categories?view=…` |
| **Reproduction** | Несколько раз подряд жать ↑↓ или менять число + OK на разных строках. |
| **Почему больно** | Каждый шаг — полный round-trip; страница «прыгает», теряется ментальная модель «куда сдвинулось». |
| **Минимальный фикс** | После успешного move — `scroll` к строке по `id` (hash/query) или toast «Категория X перемещена»; без смены архитектуры. |
| **Сложность** | S–M |

### QW-MED-01 — Медиа: только пагинация, нет поиска

| Поле | Значение |
|------|----------|
| **Severity** | Medium |
| **Workflow** | Подбор картинки для товара после загрузки десятков файлов |
| **Reproduction** | `/admin/media` — листать страницы 48 шт., искать файл глазами. |
| **Почему больно** | Много кликов; риск загрузить дубликат с другим именем. |
| **Минимальный фикс** | Поиск по `storageKey` / имени файла / `alt` (server-side filter + query param). |
| **Сложность** | M |

### QW-IMP-02 — Превью импорта: большая таблица

| Поле | Значение |
|------|----------|
| **Severity** | Low |
| **Workflow** | Импорт сотен строк (до лимита) |
| **Reproduction** | Превью — полная таблица в DOM. |
| **Почему больно** | Подвисание скролла на слабых машинах; сложно сфокусироваться на ошибках. |
| **Минимальный фикс** | Свернуть «успешные» строки в summary + expandable только errors/warnings; или виртуализация таблицы. |
| **Сложность** | M |

## Medium UX Fixes

### MED-PROD-01 — Клики до «нового товара»

| Поле | Значение |
|------|----------|
| **Severity** | Low |
| **Workflow** | Серия из 10+ новых товаров |
| **Reproduction** | Админка → Товары → «Создать» (или аналог). |
| **Почему больно** | Лишний шаг по сравнению с keyboard-first или FAB; при высокой частоте — раздражение. |
| **Минимальный фикс** | Secondary CTA «Новый товар» в шапке списка + дублирование в пустом состоянии; не менять модель данных. |
| **Сложность** | S |

### MED-PROD-02 — Slug / SEO / preview vs публичка

| Поле | Значение |
|------|----------|
| **Severity** | Medium |
| **Workflow** | Правки slug/title, проверка SEO и превью |
| **Reproduction** | Менять поля, смотреть `AdminProductPreview` и публичную карточку. |
| **Почему больно** | Если превью и прод расходятся по контракту — менеджер не доверяет превью. |
| **Минимальный фикс** | Явная подпись «превью строится из тех же полей, что …» + ссылка «открыть черновик на сайте» если есть staging. |
| **Сложность** | S (копирайт) / M (если нужна синхронизация с `buildPublicProductView`) |

### MED-CONTENT-01 — Content CMS: что реально на сайте

| Поле | Значение |
|------|----------|
| **Severity** | Medium |
| **Workflow** | `/admin/content` — правки блоков, SEO, generated поля |
| **Reproduction** | Смешение ручных полей и auto/generated badges. |
| **Почему больно** | Страх сломать прод; дублирующиеся подсказки SEO утомляют. |
| **Минимальный фикс** | Группировка «На сайт сразу» / «Только шаблон» / «Сгенерировано»; свернуть длинные hint-блоки в `<details>`. |
| **Сложность** | M |

### MED-CH-01 — Catalog health: тяжёлые таблицы

| Поле | Значение |
|------|----------|
| **Severity** | Medium |
| **Workflow** | Просмотр отчёта здоровья каталога |
| **Reproduction** | Большой объём строк в одной странице. |
| **Почему больно** | Долгий first paint, тяжёлый scroll. |
| **Минимальный фикс** | Пагинация / «показать первые N» + экспорт CSV для полного списка. |
| **Сложность** | M |

### MED-FILT-01 — Сброс фильтров при навигации

| Поле | Значение |
|------|----------|
| **Severity** | Medium |
| **Workflow** | Поиск/фильтр товаров → переход в карточку → назад |
| **Reproduction** | Зависит от реализации URL vs client state; при сбросе — менеджер повторяет фильтр. |
| **Почему больно** | Потеря контекста при back. |
| **Минимальный фикс** | Синхронизировать фильтры с `searchParams` (shareable URL). |
| **Сложность** | M–L |

## Destructive flow safety (проверка по коду / UX)

| ID | Severity | Наблюдение | Минимальный фикс | Сложность |

## Performance / responsiveness (наблюдения)

| Область | Риск | Направление |
|---------|------|-------------|
| Импорт превью | Большой HTML-таблицы | Виртуализация / срез строк |
| Медиа grid | Много превью на странице | Lazy images, меньше метаданных в первом paint |
| Товарная форма | Крупный client bundle | Разнести тяжёлые поля по `dynamic` или подгрузке |
| Catalog health | Длинные списки | Пагинация, серверная агрегация |
